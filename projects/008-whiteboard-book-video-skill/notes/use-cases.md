# 从白板视频扩展到哪些场景

保持已经验证的“分镜图片＋揭幕＋轻推近＋字幕配音”表现形式，主要更换输入材料、叙事结构和分镜内容。核心筛选标准：能否围绕一个问题，用观点、步骤、关系或对比讲清楚。

| 场景 | 输入与具体选题 | 画面组织 | 需要额外补充什么 |
| --- | --- | --- | --- |
| 开源项目导读 | README 与已核验研究；这个库解决什么问题 | 使用前后 → 能力关系 → 使用步骤 | 核验功能边界，避免把底层模型能力算给库 |
| 研究成果分享 | 报告、调研笔记；这次研究发现了什么 | 问题 → 发现 → 意义 → 结论 | 保留来源、限定条件和不确定性 |
| 知识科普 | 一个概念；缓存为什么能加速 | 请求路线、命中与未命中对比 | 审阅简化是否导致误解 |
| 产品使用教程 | 功能说明；第一次使用怎样开始 | 三步流程 → 注意事项 → 完成标志 | 精确点击教学需要加入真实录屏，库未提供录屏集成 |
| 团队培训 | SOP；遇到线上故障先做哪三件事 | 判断分支 → 角色分工 → 处理顺序 | 由业务负责人核验流程及适用条件 |
| 读书与个人表达 | 一条笔记或复盘；目标太大时先做什么 | 情境 → 观点 → 例子 → 行动 | 选择小切口，不声称一分钟覆盖整本书 |
| 系列课程 | 课程提纲；每集解释一个概念 | 固定角色、配色、开场和收尾 | 增加跨集素材管理、一致性检查与版本记录 |

## 对研究总仓库的落地方式

每个子项目可以先做一段约一分钟的视频导读：观众先理解问题与价值，再进入源码证据和完整文档。建议分三类：项目介绍片、机制解释片、场景演示片。例如 008 的制作流程介绍、002 的长内容分块机制、研究笔记转成讲解的场景。

最小制作结构：一个问题 → 两三个解释 → 一个具体例子 → 一项行动。复用现有白板规范、字幕生成器和渲染方法，按新旁白重排真实时间轴。批量生产仍需要开发统一内容模板、素材缓存、局部重做、任务队列和系列资产管理，这些不是原库已经实现的功能。

## 适用边界与验证状态

解释“为什么、是什么、如何理解”很适合；精确软件操作、产品真实外观、人物动作和连续剧情需要结合录屏、实拍或其他动画工具。保持白板效果更换主题，通常不需要更换渲染方式；改变视频表现形式则需额外实现。

**实测完成**：本项目“目标太大时，先从小动作开始”79 秒有声案例；七张分镜、MiniMax 配音、真实词级时间戳、原字幕脚本、HyperFrames 本地导出。

**适配判断**：表中其他场景未逐项制作成片。网页上的三个 30 秒内容播放器是原理示意。背景音乐与侧链混音也未在本次有声案例中验证。
