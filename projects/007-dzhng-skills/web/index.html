04 / MAKE IT OURS

把工程方法，带回我们的研究。

以下为本仓库的应用建议。
尚未集成到对应项目，也未完成效果评测。

001—002 / 内容与翻译

让每个处理阶段可复核

为解析、分块、翻译和交付分别定义契约。用任务状态与证据记录，支持续跑和局部修正。

优先借鉴：write-spec + implement-spec
003—004 / 视觉工作流

让风格判断有明确目标

固定内容与视口，逐项比较层次、排版和可读性。单双色设计的留白与低颜色数量，不应被误判为缺陷。

优先借鉴：compare-screenshots
研究总仓库 / 可持续积累

让下一次研究接得上

记录自主决策、验证证据与接手说明；用真实案例评测技能，观察返工次数和结果稳定性。

优先借鉴：audit-choices + eval-skills
可扩展方向

结构化任务状态 ／ CI 验收约束 ／ 中文排版评测 ／ Windows 工具适配

05 / VALUE UNDER SCRUTINY

模型更强了，这些规程还值得用吗？

我们的判断与待验证假设。
未进行模型效果或成本对照实验。

通用建议的价值可能下降；项目事实、验收证据和协作记录仍需要明确提供。Skill 应该证明自己的增益，而不应仅因流程完整就被默认采用。

建议的验证方式

直接模型　/　精简约束　/　完整 Skill 流程

同样的真实任务，对照成功率、漏项、返工、人工纠正次数、耗时和成本。若精简约束效果相同，就精简流程。

本仓库优先评估：任务契约、决策记录与视觉证据。通用命名、简单解释等规则按实测决定是否保留。
