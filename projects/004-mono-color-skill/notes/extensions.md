# 扩展方向与实验计划

[返回研究概览](../README.md) · [使用指南](./usage.md) · [源码与验证](./README.md)

以下是本仓库基于源码提出的扩展建议，不计入上游已有能力。当前研究网页已实现三个场景的代码构图示意、配色切换与请求草稿导出；通用配方编译、模型调用、中文生产排版及后续实验尚未实现或执行，不预先宣称质量提升。

## 按实际收益安排扩展

| 优先级 | 扩展 | 对应使用场景 | 需要新增的能力 | 验收重点 |
| --- | --- | --- | --- | --- |
| 高 | 配方解析与提示词编译 | 多人协作、不同 Agent 执行同一需求 | 明确的输入 schema、默认值、规则优先级、可保存 manifest 与编译函数 | 同一规范化输入得到同一配方；错误选项有明确反馈 |
| 高 | 中文文字独立排版 | 中文研究封面、活动海报、章节页 | 图像主体与文字分层；字体资源、行宽计算、溢出处理、SVG/PDF 或位图导出 | 标题、日期逐字准确，无缺字与溢出；修文案无需重生成主体 |
| 高 | 规则一致性校验 | 维护更多风格或持续更新规范 | 统一 palette / layout ID；检查引用、范围与条件冲突 | 留白范围、墨色方案和载体规则不存在无法解释的矛盾 |
| 高 | 真实出图评测 | 选择模型、评估 Skill 的实际收益 | 模型调用适配、结果保存、OCR、人工评审表、耗时和成本记录 | 评测读取真实图片；每个评分可追溯到输入、版本与结果 |
| 中 | 系列配方与批量管理 | 研究项目系列封面、读书卡片 | 共享参数与单张变量分离，队列、失败恢复、版本记录 | 仅重试失败项；改变文案不会无意更换全组配色 |
| 中 | 多尺寸适配 | 横版头图、方形播客封面、竖版海报 | 按尺寸重排、文字安全区域、裁切锚点 | 各比例保留主体和准确文字，不依赖直接拉伸 |
| 中 | 交互式配方预览 | 非设计人员选择方案 | 配色与版式控件、规则解释、生成前预览 | 用户能理解每个选择影响什么；预览与输出有明确对应 |
| 后续 | 真正印刷生产 | 孔版、丝网印刷、实物包装 | 色版分离、尺寸与出血、工艺参数、印厂确认及打样 | 实际色版和打样通过检查；模拟图片不作为验收替代 |

建议先解决“规则能否稳定执行、中文能否准确交付、效果能否被验证”，再增加更多风格数量。

## 面向本仓库的三个应用

### 研究封面

从各项目 `project.json` 读取编号、名称和主题，人工确认要表达的视觉隐喻，生成主体底图，再由排版程序放置准确标题与编号。`project.json` 保持现有索引职责；详细配方、模型版本和生成记录可另存到子项目，避免首页字段膨胀。

真实运行截图与概念封面分别标注。封面用于吸引阅读，不能当作某项功能已实现的证据。

### 阅读专题和章节卡片

把外刊或翻译研究中的已确认主题转成系列视觉。视觉文案先经过内容核对；模型不补造原文引句、作者署名或研究结论。大量正文继续由可编辑的文档或网页承载。

### 视觉 Skill 的对照研究

与其他视觉 Skill 比较输入格式、规则组织、默认决策和质量验证方式。若后续纳入 wibi-style，应先固定其版本并独立读码，不能直接把本项目的配方和测试机制归到另一个项目。

## 最小实验：规则和中文排版究竟带来什么收益

### 问题与分组

在同一个图像模型与输出尺寸下比较三条路径：

| 组别 | 方法 | 用来回答的问题 |
| --- | --- | --- |
| A | 普通自然语言设计请求，不加载 Skill | 基线效果如何 |
| B | 固定版本 mono-color 原版工作流 | 结构化设计规则是否改善风格一致性与构图 |
| C | mono-color 视觉规则 + 少文字底图 + 程序准确叠字 | 分层排版是否降低中文错误与修订成本 |

选“材料来源”“内容处理”“阅读应用”三个主题，每组每个主题独立生成三次，共 27 份初始结果。各组使用相同主题、准确文案、目标配色和比例。固定模型版本、输出尺寸和可用参数，记录宿主与语言模型版本。C 组先实现最小排版器才能参加实验。

A/B/C 的首轮结果单独评分；另行比较每张最多一次修正后的结果与总成本，避免只展示挑选后的最佳图片。C 组的图片生成和文字修订分别记录。

### 保存什么

每次记录任务 ID、上游 commit、模型与宿主版本、输入文案、源图及使用权限、最终提示词、配方、输出、重试原因、耗时和工具可获取的费用。无法获取的费用标记“未知”，不估造数值。即使模型支持 seed，也同时保留原始文件，不以 seed 代替结果存档。

### 怎么评估

| 指标 | 检查方法 | 注意事项 |
| --- | --- | --- |
| 文字准确性 | OCR 初筛，再人工逐字核对准确文案 | OCR 本身会误识别；不能把 OCR 通过当作最终结论 |
| 主题表达 | 隐去组别，由评审判断图片是否表达指定主题 | 不把“漂亮”与“表达正确”混成一个分数 |
| 风格一致性 | 检查同系列的纸色、色版职责、层级和质感 | 允许主体与字体变化，不能要求所有图片完全一样 |
| 构图质量 | 分别检查焦点清晰度、安静区域与可读性 | 使用预先写好的评分表，保存理由 |
| 修改成本 | 修改相同标题，记录重生成次数、排版时间与总耗时 | C 组要计入排版步骤，不能只计模型费用 |
| 失败情况 | 保存首轮错误与重试后仍失败的结果 | 不删除不美观或乱码样本 |

纸张纹理、抗锯齿、网点和叠印会产生很多 RGB 色值，因此不采用“不同像素颜色不超过两种”这种错误检查。若新增色版自动分析，需要单独建立容差与人工标注样本。

### 如何决定是否继续

若 B 相比 A 有可重复的一致性收益，才考虑把原版规则用于长期生产；若收益不明显，先检查规则冲突与模型服从程度。若 C 能保证所有必要文案准确，并降低修改同一标题的总成本，再推广到研究封面。

27 份结果只是小规模探索，不能据此宣称对所有主题和模型都有效。照片保真和印刷交付需要另建有来源图的任务集及真实打样，不能从主题封面实验推导。

## 发布进入条件

当前交付包含文档与静态交互研究网页，网页遵守总仓库稳定子路径和构建契约。未来接入出图服务时，服务端密钥不得进入静态页面。只有实际部署并验证后才填写演示地址。生成图片必须标明来源与用途，引用上游软件保留原许可证，原版示例图片不直接重新分发。
