## 建议实验：导航页项目卡片的对照审查

状态：**未执行**。

### 目标与材料

选取一个真实项目卡片作为完整范围，固定源码 commit、宿主版本、模型、推理设置、工具权限、任务文本和时间预算。保留原始实现作为基线，每轮从同一份代码开始，防止前一轮修改影响后一轮。

至少设置两组：不加载本库的基础代理；加载固定版本相关技能的代理。条件允许时每组重复三次，并由人工依据真实页面复核报告。少量重复只能作为试点证据，不能据此推断所有项目的普遍效果。

### 候选场景

| 场景 | 检查目标 |
| --- | --- |
| 常规中文标题和摘要 | 建立正常显示基线 |
| 较长中文标题、中英混排、连续 URL | 换行、裁剪、层级和完整内容入口 |
| 无封面、无演示地址 | 是否符合本仓库空值约定，是否出现失效入口 |
| 窄屏与 200% 缩放 | 内容与操作是否仍可达 |
| 键盘逐项导航 | 焦点是否清楚，链接是否有明确名称 |
| 项目实际支持的主题和动态效果设置 | 可读性与状态反馈 |

只保留实际组件支持的输入和环境；静态卡片没有加载或错误状态时不凭空制造业务状态。可以建立独立的已知缺陷副本用于评测，但不得污染正式页面。

### 指标与证据

- 发现率：人工确认的已知缺陷中，被报告的比例。
- 误报：报告后经源码和真实页面复核不成立的问题数量，并记录原因。
- 可操作性：建议能否定位到根因，是否适配原有实现。
- 修复质量：修复后原问题是否消失，是否引入新的缺陷。
- 成本：总耗时、工具调用数及宿主可提供的用量信息；不可获得的数据保持空值。
- 覆盖：实际检查了哪些页面、状态和尺寸，哪些未验证。

保留任务文本、报告、源码差异、检查命令、截图及人工判定。报告更长或术语更多不等于效果更好；优先考察正确发现与真实修复。

### 后续决策

如果试点证实某些规则稳定有用，先纳入我们的界面检查流程，再考虑自动浏览器验证和长期组件案例。中文适配与团队规范应分别记录改动，避免把上游能力与本仓库新增能力混在一起。
