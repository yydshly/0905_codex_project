04 / PRACTICAL GUIDE
我们怎样真正用起来？
把第一次出图做小，把每次判断留下来。

    
  1. 安装到支持 Skill 的 Agent
    按上游提供的安装方式执行下方命令，安装后重新开启会话。此页面不会代为安装。
    npx skills add https://github.com/nevertoday/xxd-panel-092 --skill xxd-panel-092
    来源：上游 README。安装行为和宿主兼容性尚未在本研究中实测。
  2. 准备有使用权的素材与生图通道
    先用轮廓清楚的一张照片。请 Agent 确认能够带参考图生成；安装 Skill 本身不会提供模型额度。
  3. 粘贴任务指令，生成第一张
    先选无字对照模式。能明确辨认主体后，再尝试纯设计图、多画幅和中文文案。
  4. 只重做失败项，再扩大批量
    记录变形、错字、意外裁切与重试次数。先确认单张稳定，再把同一配置应用到图片目录。

05 / CREATIVE ATLAS
还是钢笔线条，能做出什么？
从“画成线描”到“用线描表达信息”。
点击图中 01–06，查看用途、变化与可复制的创作要求。

    
最容易上手的是城市速写与局部点色；再往前可以做细节观察、拆解说明和连续故事。它们增加的是信息组织方式，不只是换一种笔触。

    
    
原有风格可直接尝试
01 / 城市速写明信片
改了什么
把完整街景压缩成有记忆点的轮廓：保留店门、窗、树和街角关系，删去杂乱背景。
用在哪里
旅行游记、城市漫步记录、个人纪念明信片。
具体任务
拍一张旅行时喜欢的小店 → 生成无字钢笔速写 → 自己补日期和一句回忆。
线条的作用
线条把注意力集中到地点特征，留白给个人文字留位置。
这里展示的是虚构街景，没有真实输入照片；实际使用时应核对地点特征。
这是独立的扩展创作要求，不是上游新增参数。01 可按纯设计图使用，05 需追加明确颜色要求；02 / 03 / 04 / 06 应另建任务规范，不能声称原库已内置支持。

    
一次看完：六种创意与场景对照
创意适用场景比单幅线描多了什么
01 城市速写游记、纪念明信片地点概括与手写留白
02 建筑注释参观笔记、设计学习整体与局部的对应关系
03 植物观察园艺、亲子写生手账主枝、叶、花的分层观察
04 物件拆解DIY、器物清洁记录部件顺序与连接关系；需真实依据
05 局部点色封面、个人邀请卡指定视觉重点
06 四格故事生活日记、旅行叙事时间顺序与人物连续性

    
我们的结论：如果只要一张漂亮的线描，风格提示词就可能足够。只有需要反复制作观察页、说明页或故事页时，才值得把它扩成专门的工作流。

    
另一条扩展 / 换一种视觉表达
不局限于钢笔，同一个街角还能这样做。
保留“素材 → 视觉规则 → 交付模式”的思路，另写一套风格配方。下面是六种独立创意，不是 092 已经提供的功能。

    
    
图号 / 新创意效果变化对应场景下一步怎样用

      
01 水彩旅行卡透明色块、柔和边缘与阳光氛围游记、个人明信片、纪念卡用自己的照片出水彩图，再后期排日期和回忆

      
02 木刻版画海报粗犷刻痕、黑白块面与强对比个人展览概念、艺术海报、刊物封面先确定主题轮廓，再测试缩小后是否仍清楚

      
03 层叠纸艺邀请彩纸叠层、切边与轻微投影生日邀请、纪念日、节日贺卡选择建筑或物件主题，另留准确文案位置

      
04 等距微缩场景把建筑变成可俯看的小模型虚构街区导览、场景概念、项目视觉真实导览需人工核对布局，成图不会自动成为 3D 模型

      
05 像素游戏场景有限色板、明确像素格与游戏感个人游戏原型、像素壁纸、场景设定继续处理网格、碰撞和图层；生成图片不是现成游戏资产包

      
06 蓝图风观察页蓝底白线、多个观察视图与技术感设计笔记、空间构思、概念展示真实尺寸和结构由专业工具另行验证，不用于施工

    

    
若我们要实现这些方向，应创建独立风格模块与验收规则，不能把原库的钢笔提示词直接当成所有风格的通用模板。本页只是创意效果验证；商业采用原库内容仍需解决上游授权。

03 / 风格档案与模型适配
统一记录风格来源、适用场景、许可与基准样本；按图像服务分别验证多图参考能力。
精确中文排版可由后处理工具完成，作为独立扩展流程。

    
与我们的研究相连
素材 → 内容 → 风格 → 交付
001 的阅读材料研究提供内容背景；002 的任务编排思路可补强批量执行；003 的风格选择与 004 的色彩规则研究，可共同形成视觉工作流的对照实验。003、004 的比较仍需进一步验证。

    
接入前需要知道的实现边界
  • 没有自带图像模型：图像桥接脚本调用兼容 API；文档列出的模型不等于全部经过适配测试。
  • 通道探测较宽松：probe 将 200、400、409、422 视为就绪，不能替代一次真实编辑与多图参考测试。
  • 尺寸校准可能裁切：write_png 使用 ImageOps.fit，目标像素正确不等于保留了完整构图。
  • 验收主要靠 Agent：没有现成的 OCR 校验或风格评分服务；compose_panel 也不判断审美。
  • 批量会放大成本：不同模式、不同画幅通常分别生成；预算估计还应包含 Agent 开销与失败重试。
